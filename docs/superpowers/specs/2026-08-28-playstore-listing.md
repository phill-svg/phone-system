## App content — the forms that actually gate the release

Play's blockers are declaration forms, not the binary. Three of these are triggered by
permissions the Twilio Voice SDK merges in from its **own** manifest
(`node_modules/@twilio/voice-react-native-sdk/android/src/main/AndroidManifest.xml`) — they do
not appear in `app.json`, so they are easy to miss until the Console rejects the release.

### 1. Foreground service permissions — REQUIRED
The SDK ships `VoiceService` with `android:foregroundServiceType="microphone"` and declares
`FOREGROUND_SERVICE_MICROPHONE`. Since Android 14 this needs a Console declaration **with a
video demonstrating the in-app flow**.

- **Permission:** `FOREGROUND_SERVICE_MICROPHONE`
- **Justification:**
```
TCB Phone is a softphone for the business's telephone number. When a staff member is on a call,
a foreground service with the microphone type keeps the call audio session alive while the app
is in the background or the screen is off — the user can switch apps mid-call without the call
dropping. The service runs only for the duration of an active call and is stopped as soon as
the call ends. Microphone audio is used solely to carry the user's voice on that call.
```
- **Video:** unlisted YouTube link showing: place a call → call connects → background the app →
  call continues → hang up → service stops. Recording this is part of the pre-submit checklist.

### 2. Full-screen intent permission — REQUIRED
The SDK declares `USE_FULL_SCREEN_INTENT` to show the incoming-call screen over the lock screen.
Play restricts this to calling and alarm apps; TCB Phone qualifies as a calling app.

- **Justification:**
```
TCB Phone is a calling app. It uses a full-screen intent to present the incoming-call screen
when a business call arrives while the device is locked or the app is in the background, so the
user can answer or decline. It is not used for any other notification.
```

## Known review risks
1. **Foreground-service video.** This is the most common Android rejection now. The declaration
   is rejected without a video that clearly shows the call continuing in the background.
2. **Closed-testing requirement.** Personal developer accounts created after 13 Nov 2023 must run
   a closed test with **12 testers for 14 continuous days** before production access unlocks.
   Organisation (business) accounts are exempt. Confirm which type the TCB account is *before*
   promising a launch date — if it is personal, the 14-day clock is the critical path and the
   `internal` track in `eas.json` is where testing starts.
3. **Staff-only app.** Play is far more relaxed than Apple here, but if questioned, the same
   framing applies: it is an internal business tool. If public listing is unwanted, use a
   **closed track** or **managed Google Play private app** distribution instead of production.
4. **Permissions the SDK adds for you.** `RECORD_AUDIO`, `POST_NOTIFICATIONS`,
   `USE_FULL_SCREEN_INTENT`, `FOREGROUND_SERVICE*`, `WAKE_LOCK`, `BLUETOOTH_CONNECT` and
   `DISABLE_KEYGUARD` are merged from the Twilio SDK manifest. Reviewers see the merged list, so
   the justification must cover them — not just the three listed in `app.json`.
