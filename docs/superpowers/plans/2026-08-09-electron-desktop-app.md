# TCB Phone Desktop Wrapper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a `desktop/` Electron app that opens a window pointed at the live TCB VoIP admin dashboard, buildable into an unsigned Windows NSIS installer named "TCB Phone".

**Architecture:** A self-contained Node package in `desktop/` (own `package.json`, no monorepo tooling), with a single CommonJS main-process file (`main.js`) creating one `BrowserWindow` that loads `https://tcb-voip.phill-abb.workers.dev/`. Packaged via electron-builder (config inlined in `package.json`). No preload script, no IPC, no icon asset, no automated tests — matches the approved design spec exactly.

**Tech Stack:** Electron (main process only, CommonJS), electron-builder (NSIS/Windows target). Matches spec at `docs/superpowers/specs/2026-08-09-electron-desktop-app-design.md`.

## Global Constraints

- App name everywhere it's user-visible (window title, desktop shortcut, Start Menu entry, `productName`): exactly `TCB Phone`.
- Dashboard URL is hardcoded to `https://tcb-voip.phill-abb.workers.dev/` — no config file, no env var, no CLI flag.
- No preload script, no IPC, no custom app icon, no automated test suite — these are deliberate v1 exclusions per the spec, not gaps to fill in.
- `webPreferences` must include `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webviewTag: false` — do not weaken these.
- No `will-navigate` origin-lock handler — the spec explicitly rejects this (it would break the Cloudflare Access login redirect). Do not add one "for security" — see spec's "Deliberately no origin-lock" section for the full reasoning.
- `nsis.perMachine` must be `false` (per-user install, no admin rights required) and `nsis.oneClick` must be `true`.
- electron-builder output directory is `release` (not the default `dist`).
- Don't hand-copy any Electron/electron-builder version numbers as final — `npm install --save-dev electron@latest electron-builder@latest` and commit whatever it actually resolves to.

- [ ] **Step 4: Write `desktop/main.js`**

```js
"use strict";

const { app, BrowserWindow, shell } = require("electron");

// Single source of truth for the dashboard URL. If the worker is ever moved
// to a custom domain, update this one line.
const DASHBOARD_URL = "https://tcb-voip.phill-abb.workers.dev/";

function createWindow() {
  const win = new BrowserWindow({
    width: 1280,
    height: 800,
    minWidth: 800,
    minHeight: 600,
    title: "TCB Phone",
    autoHideMenuBar: true, // no custom menu items needed for a pure wrapper
    webPreferences: {
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true,
      webviewTag: false,
    },
  });

  // Any window.open()/target="_blank"/popup request is denied in Electron
  // and handed to the OS default browser instead. The dashboard has no
  // external links today, so this never fires in normal use — it's cheap
  // standard security practice against a page that could change in the
  // future, not a response to a current requirement.
  win.webContents.setWindowOpenHandler(({ url }) => {
    shell.openExternal(url);
    return { action: "deny" };
  });

  win.loadURL(DASHBOARD_URL);

  return win;
}

app.whenReady().then(() => {
  createWindow();

  app.on("activate", () => {
    // macOS-only pattern (re-create a window when the dock icon is clicked
    // with no windows open). Harmless no-op on Windows; included because
    // it's standard Electron boilerplate and costs nothing to keep.
    if (BrowserWindow.getAllWindows().length === 0) {
      createWindow();
    }
  });
});

app.on("window-all-closed", () => {
  // Standard cross-platform pattern: quit on all-windows-closed everywhere
  // except macOS. This app is Windows-only in practice, so this always
  // quits the app when the window is closed — no tray, no background
  // process, per the "pure wrapper" scope decision.
  if (process.platform !== "darwin") {
    app.quit();
  }
});
```

Do not add a `will-navigate` handler restricting navigation to the worker's origin — see Global Constraints above.

# TCB Phone — Desktop App

A thin Electron wrapper around the TCB VoIP staff admin dashboard
(https://tcb-voip.phill-abb.workers.dev/). It's just a window pointed at the

## Building the installer

```bash
cd desktop
npm install
npm run build
```

## Distributing to staff

1. Build the installer locally (above).
2. Upload the `.exe` to a new [GitHub Release](https://github.com/phill-svg/phone-system/releases) on this repo.
3. Share the release download link with staff.

There is no auto-update. Re-distribute a new installer (and ask staff to
re-run it) only when the desktop shell itself changes — not for normal
dashboard updates, which are live immediately for everyone.

## Heads-up for whoever shares the download link

The installer is **not code-signed** (no code-signing certificate — that's a
paid service and not worth it for an internal tool with a handful of users).
Windows SmartScreen will show a blue "Windows protected your PC" warning the
first time someone runs it. This is expected, not a sign of a broken or
malicious file. Tell staff in advance:

> Click **"More info"**, then **"Run anyway"**. This screen shows up because
> the app isn't from a large publisher registered with Microsoft, not because
> anything is wrong with it.

## Local dev run

```bash
cd desktop
npm install
npm start
```

- [ ] **Step 8: Manual verification — dev run and cold-login check**

```bash
cd desktop
npm start
```

Expected: a window opens, sized 1280×800, title bar reads "TCB Phone", no menu bar visible.

Then perform the cold-login check — this is the check that actually validates the Cloudflare Access redirect works inside Electron, since a warm/already-logged-in session would skip the redirect entirely and hide a broken handler:

1. Close the app.
2. Delete the folder `%APPDATA%\TCB Phone` if it exists (Electron's per-app userData folder, keyed off `productName`).
3. Run `npm start` again.
4. Expected: the window navigates to the Cloudflare Access one-time-PIN login page (`phill-abb.cloudflareaccess.com`). Enter the PIN sent to an `@tcbpestcontrolcanberra.com.au` address.
5. Expected: after submitting the PIN, the same window redirects back and lands on `/admin/live`, showing the dashboard.

If step 5 fails (window shows an error, or gets stuck on the Access page), stop and report — do not proceed to Step 9 until login works.
