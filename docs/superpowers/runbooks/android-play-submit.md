# Runbook: build and submit TCB Phone to Google Play

Listing copy, declarations and demo credentials live in
`../specs/2026-08-28-playstore-listing.md`. This file is the mechanical path from a clean
checkout to a build sitting on a Play track.

Like the iOS runbook, this **cannot be automated from CI here** — it needs a Google Play
Console account, a Google Cloud service account key, and an `eas` login. Run it from a machine
signed in to both.

Everything below runs from `mobile/`.

---

## 0. One-time: Play Console + service account

1. **Create the app** in the Play Console: *All apps → Create app*.
   - App name `TCB Phone`, language English (Australia), type **App**, **Free**.
   - Package name is set by the first upload and is **permanent**:
     `au.com.tcbpestcontrolcanberra.tcbphone`.

2. **Upload the first bundle by hand.** The Google Play Developer API cannot create an app's
   *first* release — `eas submit` will fail with a "package not found" style error until at
   least one AAB has been uploaded through the Console UI. So: run step 1 below, download the
   `.aab`, and upload it manually to the **Internal testing** track once. Every later release
   can go through `eas submit`.

3. **Create the service account** so `eas submit` can authenticate:
   - Play Console → *Setup → API access* → link a Google Cloud project.
   - In Google Cloud → *IAM & Admin → Service Accounts* → create one → *Keys → Add key → JSON*.
   - Back in Play Console → *Users and permissions* → invite the service-account email and grant
     **Release manager** (or at minimum: view app information, manage releases on the tracks you
     will submit to).
   - Save the JSON as `mobile/credentials/play-service-account.json` — the path
     `eas.json` points at. That directory is gitignored (as are `play-service-account*.json`,
     `*.keystore` and `*.jks`); **never commit the key**.

4. **Signing.** Let EAS generate and manage the upload keystore (`eas credentials` shows it) and
   enrol in **Play App Signing**. Back the keystore up — losing it means you can no longer ship
   updates to the same listing.

---

## 1. Build the release bundle

```bash
cd mobile
npx eas login                # skip if already signed in
npx eas build --profile production --platform android
```

The `production` profile builds an **app-bundle** (`.aab`), which is what Play requires;
`preview` builds an APK for sideloading and must not be uploaded. `autoIncrement` bumps
`android.versionCode` in `app.json` on each production build — commit that bump.

Sanity checks once the build finishes:

```bash
# targetSdk must meet Play's floor for new submissions (35 at time of writing).
# Expo SDK 54 targets API 36; confirm rather than assume:
npx expo prebuild --platform android --no-install
grep -rn "targetSdkVersion" android/build.gradle android/gradle.properties
```

Confirm in the EAS build logs that the merged manifest carries the Twilio permissions
(`FOREGROUND_SERVICE_MICROPHONE`, `USE_FULL_SCREEN_INTENT`, `BLUETOOTH_CONNECT`, …). They come
from the SDK's own manifest, not `app.json`, and they drive the Console declarations.

> `android/` is gitignored and regenerated by prebuild — delete it after inspecting, or leave
> it; EAS builds from a clean prebuild either way.

---

## 2. Install and verify before submitting

Install the AAB on a real device (`bundletool`, or build a `preview` APK from the same commit)
and check the things that only break on Android:

- [ ] Launcher icon is the full TCB shield, not a cropped one — check on a **circular** launcher
      icon shape (Pixel default). This is what `android-adaptive-foreground.png` fixes.
- [ ] Sign in with the demo account.
- [ ] Place an outbound call; confirm audio both ways.
- [ ] Receive an inbound call **with the app backgrounded and the screen locked** — the
      full-screen incoming-call UI must appear. If it never rings, `TWILIO_PUSH_CREDENTIAL_SID_ANDROID`
      is missing/wrong in the deployed Worker, or the FCM V1 credential isn't on the Twilio push
      credential.
- [ ] Switch apps mid-call — the call must survive (this is the foreground service, and it is
      what the declaration video has to show).
- [ ] Pair a Bluetooth headset and switch the audio route in-call. On Android 12+ the app now
      asks for Bluetooth permission at registration; if it is denied, only earpiece/speaker
      appear — that is expected.
- [ ] Send and receive an SMS; open a Messenger thread.
- [ ] Voicemail arrives with a transcription and a notification.

**Record the foreground-service demo video during this pass** — place a call, background the
app, show the call still connected, hang up. The Console declaration is rejected without it.

---

## 3. Submit

```bash
npx eas submit --profile production --platform android --latest
```

This uploads the most recent Android build to the **internal** track with
`releaseStatus: "completed"`, per `submit.production.android` in `eas.json`. To ship elsewhere,
either change `track` (`internal` → `alpha` → `beta` → `production`) or promote the release in
the Console.

Then, in the Console, complete everything under **App content** and **Store listing** from the
spec — the release will not go live until all of it is filled in, regardless of a successful
upload.

## Rollback / troubleshooting

- **`eas submit` fails with a package/app-not-found error** → the first bundle has not been
  uploaded manually yet (step 0.2), or the service account lacks Release manager on this app.
- **"Version code N has already been used"** → `android.versionCode` did not increment. Bump it
  in `app.json` and rebuild; version codes can never be reused, even for deleted releases.
- **Console rejects the release for a missing declaration** → almost always the
  foreground-service form (missing video) or full-screen intent. See the spec's *App content*
  section.
- **Incoming calls never ring on the store build, but work in dev** → the production build uses
  the production FCM credential path. Check `TWILIO_PUSH_CREDENTIAL_SID_ANDROID` on the deployed
  Worker and that `google-services.json` matches the package name.
- **Icon looks cropped on device** → `adaptiveIcon.foregroundImage` must point at
  `android-adaptive-foreground.png` (artwork inside the centre 60% of the canvas), not at the
  full-bleed `tcb-logo.png`. Regenerate with `python3 scripts/make-play-assets.py`.
- **Locked out of updates** → the upload keystore was lost. With Play App Signing enabled, Google
  can reset the upload key; without it, the listing is unrecoverable.
